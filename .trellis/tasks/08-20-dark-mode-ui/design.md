# 黑夜模式 UI 技术设计

## Visual Thesis

“午夜旧书桌”：用深浓咖啡色环境、炭褐纸张层、暖象牙墨色、铜锈强调和低饱和苔绿构成安静的夜间写作空间；层级依靠明度、细边界和留白，而不是发亮白卡、厚边框或装饰渐变。

## Content Plan

这是产品工作区，不增加营销式 Hero。视觉处理按四个层级展开：

1. 应用环境：`body` 与工作区底色，负责建立夜间氛围。
2. 导航与主工作面：侧栏、页面主面板、阅读器和编辑器，负责主要操作。
3. 次级上下文：筛选器、元信息、历史/轨迹、表格和空状态，负责信息分组。
4. 临时表面：Popover、Dropdown、Dialog、Tooltip，负责短时交互并保持最高可辨识度。

## Interaction Thesis

- 主题切换沿用当前即时切换机制，只让已有颜色/阴影 transition 自然过渡，不新增全屏动画。
- hover 通过轻微明度和边框变化表达，不在暗色表面增加发光效果。
- focus 使用铜色边框/环保证键盘定位；所有动作维持现有短时长，并保留 reduced-motion 行为。

## Architecture and Boundaries

### Global token layer

扩展 `src/style.css` 的 light/dark 根变量，提供可跨组件复用的语义契约：

- 环境：页面背景渐变、噪声混合模式、遮罩。
- 表面：侧栏、主面板、次级面板、浮层、控件、悬停/选中。
- 内容：现有 `--text-*`、代码/引用/表格专用背景与边界。
- 反馈：现有 accent/moss/gold/danger 保持语义，必要时仅调整暗色值。
- 深度：暗色阴影取消浅色 inset 高光，使用低透明黑色与细暖灰边界。

组件只消费语义变量，不自行判断当前主题。只有第三方 DOM 无法完全用变量表达时，才使用 `:root[data-theme='dark']` 或 scoped `:global()` 覆盖。

### Component migration

按用户路径而不是文件数量分批迁移：

1. 全局和框架：`style.css`、`WorkspaceShell.vue`、`SettingsPanel.vue`、`GlobalSearchPanel.vue`。
2. 核心内容：首页、笔记列表/详情、日记阅读页面。
3. 写作表面：笔记/日记编辑器与共享 editor components、Markdown 样式。
4. 辅助路由：知识对话、RAG 链路、Token 用量、标签、图片、上传和回收站。

迁移只替换主题相关颜色、边框、阴影和必要的背景图层，不调整 DOM、数据流或组件职责。

### Third-party surfaces

- Element Plus：在 `style.css` 中继续使用 `body .el-*` 命名空间，并把组件背景/文字/边框映射到主题变量。
- Toast UI：在编辑器拥有者或 `styles/markdown.css` 中使用已有的 `:deep()`/命名空间规则，覆盖编辑区、工具栏、弹层、表格、代码和分割线。
- 原生滚动条：使用低对比主题色，不影响可操作性。

## Compatibility

- `theme.js` 的存储键、事件和 system/light/dark 行为保持不变。
- 当前使用语义变量的组件无需改动；固定浅色值替换成白天等价值，因此默认主题视觉保持稳定。
- 不添加依赖，不更改 API，不引入新状态管理或全局组件层。

## Validation Strategy

- 自动验证：生产构建；Playwright 验证黑夜模式切换、刷新持久化、代表页面路由与浏览器错误。
- 视觉验证：桌面 1440×900 与移动 390×844 截图，至少覆盖首页、列表、详情/编辑、知识对话和设置浮层。
- 对比验证：使用小型只读脚本计算核心 token 的正文/表面对比度，目标至少 4.5:1。
- 回归验证：切回白天模式检查核心页面，确保变量迁移未改变结构或造成明显色差。

## Rollback

改动集中在 CSS 变量和组件样式，不涉及数据迁移。若第三方覆盖造成回归，可按“全局 token → 核心页面 → 编辑器 → 辅助路由”的提交/差异边界逐段回退。
