# 优化黑夜模式 UI

## Goal

让 MoonBirdNotes 的黑夜模式成为完整、统一、可长时间阅读和写作的“午夜旧书桌”界面，而不是在浅色页面外套一层深色背景。用户切换到黑夜模式后，工作区、主要内容面板、阅读器、编辑器和浮层都应具有明确的暗色层级，同时保持现有功能、布局和白天模式不变。

## Background

- 当前主题状态和持久化已由 `src/utils/theme.js` 统一管理，支持跟随系统、白天和黑夜三种模式。
- `src/style.css:43` 已定义基础暗色变量，但 `body` 的背景仍使用固定浅色渐变，且第二轮页面视觉样式经常覆盖前面已经使用变量的规则。
- 代码审计发现 26 个 Vue/CSS 文件中有 103 处固定浅色背景声明。集中区域包括 `DiaryView.vue`（23 处）、`NoteListView.vue`（14 处）、`NoteDetailView.vue`（8 处）、`KnowledgeChatView.vue`（6 处）、`HomeView.vue`（6 处）及编辑器浮层。
- 现有专属暗色选择器主要位于 `DiaryView.vue` 和全局样式，覆盖范围不足。历史会话 `019f110a-fbd6-7ad3-b297-63a484d8bcca` 也记录了正文、代码块和分割线需要多次局部修复，说明继续追加单点覆盖不能解决根因。
- `WorkspaceShell.vue:158` 的侧栏渐变、`WorkspaceShell.vue:358` 的激活导航，以及 `HomeView.vue:1067` 之后的截图匹配样式仍使用固定浅色值，是明显的白色孤岛来源。

## Requirements

### R1. 统一暗色语义层级

- 在全局主题变量中补齐页面背景、侧栏、主面板、次级面板、悬浮层、输入控件、代码区域、分割线和交互状态所需的语义色。
- 暗色主题采用深棕黑背景、炭褐纸张、暖白文字、铜色强调和低饱和苔绿；大面积区域不得使用纯黑或纯白。
- 白天主题使用与当前视觉等价的变量值，避免迁移变量时改变既有白天观感。

### R2. 消除主要流程中的浅色孤岛

- 工作区侧栏、导航、首页和全局搜索/设置浮层必须完整适配黑夜模式。
- 笔记列表、笔记详情、笔记编辑、日记阅读/编辑、标签、图片、回收站和上传页面的主要容器、工具栏、筛选器、表格、空状态必须使用主题表面变量。
- 知识对话、RAG 链路和 Token 用量页面的消息、筛选器、轨迹/历史面板和数据区域必须使用主题表面变量。
- Element Plus 对话框、Popover、Dropdown、Select、Input 等共享控件必须继承相同的暗色层级。

### R3. 阅读与编辑可读性

- 标题、正文、辅助文字、链接、代码、引用、表格和分割线在暗色主题下有清晰但不过亮的对比。
- 正文与重要控件文本目标对比度不低于 4.5:1；辅助文本仍需清晰可辨。
- Toast UI Editor/Viewer 与 Markdown 内容不得残留白色编辑区、表格单元格、代码块或分割线。

### R4. 保持行为与响应式布局

- 不改变路由、数据请求、编辑器命令、主题持久化和设置面板行为。
- 不改变现有桌面/移动布局结构；黑夜模式在窄屏下不能产生新的水平滚动或遮挡。
- 保留现有短促、克制的 hover/focus/主题切换反馈，并继续尊重 `prefers-reduced-motion`。

## Acceptance Criteria

- [ ] 设置为黑夜模式后，`html[data-theme='dark']` 即时生效并在刷新后保持。
- [ ] 首页、笔记列表、笔记详情、笔记编辑、日记、知识对话、RAG 链路、Token 用量以及设置/搜索浮层不再出现与白天模式相同的大面积浅色表面。
- [ ] 侧栏、页面背景、主/次面板、输入控件、表格、编辑器/阅读器和浮层之间至少形成三层可辨识的暗色明度层级。
- [ ] 正文、标题、辅助文字、链接、代码块、引用、表格和分割线在暗色主题下清晰可读，正文关键组合满足 4.5:1 对比度目标。
- [ ] 白天模式的颜色、布局和交互没有可见回退。
- [ ] 桌面和移动视口完成代表性页面截图检查，不出现白色孤岛、文字不可读、溢出或控件状态不清。
- [ ] `npm run build` 通过；主题切换/持久化与代表性路由的 Playwright 检查通过，浏览器无页面错误。

## Out of Scope

- 不重做页面信息架构、导航结构或业务功能。
- 不新增主题种类、主题自定义器、后端接口或数据库字段。
- 不更换现有品牌图片、插画、图标体系和字体。
- 不把本任务扩大为所有历史 CSS 的通用重构；只迁移与主题视觉直接相关的颜色、边框和阴影。

## Risks and Deferred Items

- Toast UI 和 Element Plus 内部样式具有较高选择器优先级，需要使用现有的局部 `:deep()` 或受控全局覆盖，不能新增无命名空间的广泛规则。
- 图片本身的亮度不在本任务内；可通过暗色蒙层或容器处理降低突兀感，但不编辑图片资产。
- Vite 现有大分块警告不属于本任务，只要生产构建成功即可。
