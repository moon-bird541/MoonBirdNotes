# RAG Agent 第 09 步开发记录：实现单篇笔记索引

> 日期：2026-07-14  
> 状态：已完成  
> 对应文档：`agent开发/RAGAgent开发步骤.md`

## 本次完成的范围

本次完成 RAG Agent 实际执行顺序的第 9 步：实现 `index_note(note_id)` 和 `delete_note_index(note_id)`，把单篇 MySQL Note 的最新原文转换为父片段、子片段、在线 Embedding 和 Qdrant Point，并在全部新数据准备完成且 Note 快照未变化后切换 `RagIndexState`。

本步还落实了首次真实云端索引前必须完成的逐篇授权边界：新增默认关闭的 `ai_indexing_enabled`。本次没有实现保存后自动排队、任务防抖或后台 Worker，这些属于第 10 步。

## 做了什么

### 逐篇 AI 索引开关

为 `Note` 新增：

~~~text
ai_indexing_enabled: bool = false
~~~

- 普通笔记和日记共用该开关。
- 默认值为 `false`，数据库迁移不会让任何已有内容自动参与云端索引。
- `index_note` 在调用 tokenizer、硅基流动或 Qdrant 前强制检查开关。
- 未开启时返回 `ai_indexing_disabled`，不创建索引状态，也不产生外部请求。
- 已软删除的 Note 返回 `note_deleted`，不会重新进入索引。
- Django Admin 列表和过滤器可以查看并逐篇管理该开关。

真实数据库应用迁移后，现有 19 篇 Note 全部保持 `ai_indexing_enabled=false`，本步没有索引任何用户笔记。

### 稳定 tokenizer 配置

新增 `RAG_TOKENIZER_FILE`。本地环境配置为项目 `.tmp` 下 Git 忽略的 BGE-M3 tokenizer，生产索引服务直接加载该文件：

- 不加载本地模型权重。
- 不在每次索引时临时下载 tokenizer。
- 父片段、子片段和硅基流动使用同一个 `BAAI/bge-m3` token 口径。

### Note 全快照

索引开始时读取：

~~~text
note_id
title
markdown_content
is_deleted
ai_indexing_enabled
普通笔记 tags
日记 diary_date / mood / weather / summary
~~~

`source_hash` 继续严格表示完整 Markdown 的 SHA-256，符合已有数据契约。

另外计算只在索引流程内部使用的 `snapshot_hash`，覆盖标题、正文、开关、删除状态、标签和日记字段。这样即使 Markdown 没变，但标题、标签、心情或摘要在 Embedding 期间发生变化，旧向量也不会被激活。

### 父子片段与确定性 ID

索引服务复用第 4～6 步已经验证的解析与分块实现：

~~~text
最新 Note Markdown
→ split_parent_chunks
→ split_child_chunks
→ embed_documents
~~~

父片段 UUID 使用固定 namespace 的 UUID5，输入包含：

~~~text
note_id + index_version + parent_chunk_index + section_hash
~~~

Qdrant Point UUID 使用另一个固定 namespace 的 UUID5，输入包含：

~~~text
parent_id + child_chunk_index + chunk_hash
~~~

同一 Note、同一目标版本和同一输入发生安全重试时会得到完全相同的父片段 ID 和 Point ID，不会因为随机 UUID 产生重复 Point。

### Qdrant Payload 扩展

在第 8 步基础 Payload 上增加：

~~~text
content
chunk_hash
~~~

- `content` 保存当前子片段原始 Markdown，用于后续返回 `matched_child_excerpt`。
- `chunk_hash` 对应第 6 步完整 `vector_text` 哈希，用于缓存和变化追踪。
- 两者都是可重建派生数据，不建立额外 Payload Index。
- 新增按 `note_id` 删除全部版本的 Qdrant 操作，供 `delete_note_index` 使用。

### 单篇索引流程

`index_note` 实际流程：

~~~text
读取并校验 Note 快照
→ 锁定 RagIndexState，确定目标版本
→ 标记 indexing，但保留旧激活字段
→ 生成父片段和子片段
→ 一次批量调用 embed_documents
→ 再次锁定并校验 Note 全快照
→ 保存目标版本父片段
→ 清理同目标版本的失败残留 Point
→ 批量 Upsert 新 Point
→ 再次锁定并校验 Note 全快照
→ 切换 RagIndexState 到 completed
→ 清理旧版本 Qdrant Point 和父片段
~~~

新版本激活前不会删除旧版本。MySQL 与 Qdrant 无法组成一个跨数据库事务，因此通过“先完整写新版本、最后切状态、再删旧版本”的顺序保证失败时不会破坏真实 Note，也不会把半成品当成当前索引。

### 索引状态与版本

- 首次成功使用版本 1。
- 已有成功版本时，新尝试使用当前版本加 1。
- 失败尝试不推进激活版本，重试继续使用同一目标版本和确定性 ID。
- 成功后记录 `source_hash`、模型、Embedding 版本、索引版本和 `indexed_at`。
- 空 Markdown 可以完成零父片段、零 Point 的合法索引状态。
- 同一 Note 已处于 `indexing` 时，第二个同步调用返回可重试的 `indexing_in_progress`。

### 并发变化防护

在保存父片段前和 Qdrant Upsert 后各校验一次全快照，并在最终切换状态时锁定 Note 与状态行。

如果正文或元数据变化：

- 返回可重试的 `note_changed_during_indexing`。
- 不激活旧快照结果。
- 删除本次目标版本父片段。
- 尽力清理本次目标版本 Qdrant Point。
- 状态标记为 `failed`，保留可诊断的安全错误码。

### 失败恢复

- Embedding 失败：不保存新父片段、不写新 Point，旧激活字段和旧父片段保留。
- Qdrant Upsert 失败：删除本次新父片段并尽力清理目标版本 Point。
- 未知依赖错误：统一转换为 `indexing_unexpected_error`，不把 Provider 响应正文写入状态表。
- 旧版本清理失败：新版本已经完整可用，因此保持 `completed`；在 `error_message` 写入 `cleanup_pending` 和版本号，旧父片段继续保留，供后续重试清理。
- `RagIndexState.status` 表示最近一次索引尝试的真实状态；失败不会伪报完成。

### 删除索引

`delete_note_index(note_id)`：

1. 拒绝删除仍处于 `indexing` 的 Note。
2. 先按 `note_id` 删除 Qdrant 全部 Point。
3. Qdrant 成功后，在 MySQL 事务中删除父片段和索引状态。
4. 不修改或删除真实 Note。

如果 Qdrant 不可用，MySQL 父片段和状态保持不变，调用方可以安全重试。

### 公开服务边界

`rag.services` 公开：

~~~text
index_note
delete_note_index
IndexNoteResult
DeleteNoteIndexResult
NoteIndexingError
~~~

其他 Django App 不需要直接依赖分块器、Embedding 客户端、Qdrant 客户端或 RAG 模型内部细节。

### 代码注释

新增代码包含必要中文模块说明、类说明和关键分支注释，重点解释逐篇授权、全快照哈希、UUID5 输入、跨数据库切换顺序、失败清理和旧版本延迟清理原因。

## 为什么这样做

- 第九步会首次把真实子片段发送到硅基流动，因此默认关闭的逐篇开关必须先于自动索引流程完成。
- 仅比较 Markdown `source_hash` 无法发现标题、标签和日记元数据变化；内部全快照哈希补足并发校验，但不改变既有 source_hash 数据契约。
- 确定性 UUID 让同目标版本重试覆盖相同 Point，避免超时后不知道 Provider 是否成功而产生重复数据。
- 旧版本在新版本激活后再删除，使 Embedding 或 Qdrant 故障不会提前破坏当前索引。
- Qdrant 旧 Point 即使因清理故障暂时残留，也无法通过当前 `RagIndexState.index_version` 成为有效结果；对应父片段暂时保留，便于以后继续清理。
- 删除外部数据失败时保留 MySQL 派生状态，比只删一半后声称成功更容易安全重试。
- 第十步才负责异步排队和防抖；本步保持同步、确定性接口，便于后台 Worker 直接复用和独立测试。

## 自动化测试

新增 18 个单篇索引专项测试，覆盖：

- 未逐篇授权时零外部调用。
- 软删除 Note 禁止索引。
- 普通笔记完整成功路径和 Payload。
- 日记日期、心情与标签隔离。
- 空 Markdown 零片段索引。
- Embedding 失败保留旧激活字段和旧父片段。
- Qdrant 失败清理新父片段并标记失败。
- 部分失败重试复用相同确定性 Point ID。
- 连续成功只保留当前父片段版本。
- Embedding 期间正文变化时停止写入。
- Upsert 后标题变化时不激活并清理目标版本。
- 旧版本清理失败时新版本继续可用。
- 未知依赖错误正文脱敏。
- 同步索引冲突。
- 非法和不存在的 note_id。
- 删除全部派生索引但保留真实 Note。
- Qdrant 删除失败时保留 MySQL 状态。
- 索引进行中禁止删除。

第 8 步 Qdrant 测试扩展到 20 个，新增完整 Payload 字段和整篇删除过滤验证。

## 真实端到端验证

只创建一篇不含私人内容的合成 Note，并显式设置 `ai_indexing_enabled=true`，使用真实：

~~~text
BAAI/bge-m3 tokenizer
硅基流动在线 BAAI/bge-m3
本地独立 Qdrant 1.18.2
真实 MySQL RagParentChunk / RagIndexState
~~~

连续执行两次 `index_note`：

~~~text
第一次版本：1
第二次版本：2
第一次 Qdrant Point：2
第二次 Qdrant Point：2
Point 数稳定：是
RagIndexState：completed / version 2
MySQL 父片段版本：[2]
delete_note_index 删除父片段：2
删除后 Qdrant Point：0
~~~

验证结束后已删除合成 Note、父片段、状态和全部 Qdrant 测试 Point。现有 19 篇用户 Note 全部保持 AI 索引关闭，Qdrant 当前 Point 数为 0。
