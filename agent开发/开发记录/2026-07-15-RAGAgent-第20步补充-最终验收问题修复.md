# RAGAgent 第 20 步补充：最终验收问题修复

日期：2026-07-15

## 本次做了什么

1. 在 Knowledge Agent 调用模型前，由服务器固定执行首轮只读检索：
   - 精确单日日记查询直接调用 `get_diary_by_date`。
   - 其他问题先调用 `search_notes(top_k=5)`，再批量调用一次 `get_parent_chunks`。
2. 服务器预检索结果以明确标记为“不可信正文”的 system 上下文交给 DeepSeek，不伪造 assistant/tool 调用历史。
3. 日记读取结果增加 `available_fields`、`missing_fields` 和与索引一致的 `heading_path`。
4. 当用户询问日记中为空的心情、天气或摘要字段时，服务器强制返回资料不足，不允许模型猜测。
5. 最终来源只保留模型列出的第一个、且已经被服务器验证的来源，避免把相关但不能直接支持结论的章节附带为依据。
6. 父片段中的精确小节允许成为候选来源，以支持搜索根片段无法直接表达的细粒度章节。
7. 评测集增加可选的 `acceptable_source_heading_paths`，回答来源评测与检索章节命中评测使用各自口径。
8. 为 `skill-name-conflict-35` 补充真实可接受的精确小节路径，不降低来源正确率门槛。
9. 修复 embedding 工厂测试的进程级缓存隔离问题，并补充服务器预检索、空字段拒答和来源收敛测试。

## 为什么这样做

- 原来的四步工具规划主要交给模型，导致相同问题可能选择不同父片段或整篇笔记，来源不稳定。
- DeepSeek v4 会拒绝服务器伪造的工具调用历史，因此预检索结果必须作为普通系统上下文传入。
- 日记字段存在但值为空时，模型仅靠提示词仍可能使用常识猜测，必须由服务器做硬约束。
- 父片段用于补充回答上下文，但模型容易附带多个相关章节；只保留首个已验证直接来源可以提高引用精度，同时不允许伪造来源。
- 检索期望路径和回答可接受路径并不总是相同，二者分离可以修复标注漏项，同时继续保持 100% 来源正确率要求。

## 兼容性说明

- 未向 DeepSeek v4 请求体发送 `temperature`。实测当前官方接口会拒绝本项目带该字段的调用，因此确定性主要通过服务器预检索、来源白名单和硬性拒答规则实现。
- Knowledge Agent 仍然只有六个只读工具，没有新增 Note Agent、Settings Agent 或任何写工具。

## 结论

第 20 步最终验收问题已经修复，Knowledge Agent 继续保持只读边界。后续如要建设写能力，仍应单独设计权限、确认、审计和回滚机制，不能直接给当前 RAG Agent 增加写工具。
