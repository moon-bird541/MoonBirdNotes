# RAG Agent 第 06 步开发记录：实现子片段分割

> 日期：2026-07-14  
> 状态：已完成  
> 对应文档：`agent开发/RAGAgent开发步骤.md`

## 本次完成的范围

本次完成 RAG Agent 实际执行顺序的第 6 步：只在单个父片段内部生成用于向量召回的子片段，并处理完整向量文本 token 上限、代码块、列表项、表格行、同章节重叠、业务元数据、`parent_id` 和稳定 `chunk_hash`。

本次没有调用硅基流动 Embeddings API 批量生成向量，也没有写入 Qdrant；这些属于后续步骤。

## 做了什么

### 子片段数据契约

新增 `ChildChunkConfig`：

~~~text
target_tokens: 默认 350
max_tokens: 默认 500
overlap_tokens: 默认 50
~~~

配置会拒绝非正数目标、低于目标的最大值，以及大于或等于目标值的重叠配置。

新增 `ChildChunk`：

~~~text
parent_id
chunk_index
heading_path
content
vector_text
token_count
overlap_token_count
chunk_hash
~~~

每个子片段显式保存 `parent_id`，后续 Qdrant 命中后可以回查 MySQL 中的 `RagParentChunk`。

### 普通笔记与日记元数据

新增 `RagDocumentMetadata`，严格区分：

- 普通笔记：标题和普通笔记标签。
- 日记：日期、标题、心情、天气和摘要。
- 日记禁止携带普通笔记标签。
- 普通笔记禁止携带日记专属字段。
- 日记必须提供日期。

向量文本按文档规范生成固定格式，并补充完整标题路径。无标题路径时明确使用“未分节”。

### 向量正文净化

- Markdown 图片只保留有意义的 alt，不把本地或远程图片路径发送给 Embedding API。
- Markdown 链接只保留可见文字，不把精确 URL 放入向量文本；URL 继续由关键词检索通道处理。
- 行内代码保留可见代码内容。
- 围栏代码保留语言和代码正文。
- Markdown 标题、列表、引用和表格保留可见语义。
- HTML 标签从向量正文移除，只保留可见文字。

子片段的 token 上限按“业务元数据 + 标题路径 + 净化后的正文”完整计算，而不是只计算原始正文。

### 标题路径

- 从父片段共同标题路径继续维护具体子章节路径。
- 父片段由多个短兄弟章节合并时，子片段会恢复各自具体的标题路径。
- 首个标题与父片段末级标题相同时不会重复追加。
- 新的 H1/H2/H3/H4 等标题会按层级弹出已经结束的同级或子级路径。
- 不同具体标题路径会强制结束当前子片段，因此不会跨章节添加固定重叠。

### 代码块

- 完整代码块连同向量元数据未超限时保持原子，不进行切分。
- 超长代码块只在完整代码行之间切分。
- 每个超长代码片段重复开始围栏和结束围栏，保留语言标记。
- 单个代码行连同围栏和元数据仍超过上限时返回 `ChildChunkingError`，不生成超限向量。
- 代码块不作为重叠内容重复到下一子片段。

### 列表

- 列表整体能放入时保持完整。
- 长列表只在顶层完整列表项之间切分。
- 嵌套内容随所属顶层列表项一起保留。
- 单个列表项超过上限时明确失败，不从列表项中间截断。

### 表格

- 表格整体能放入时保持完整。
- 长表格只在完整数据行之间切分。
- 每个表格子片段重复原始表头和表头分隔行。
- 单个数据行连同表头和元数据仍超过上限时明确失败。
- 拆分后的表格片段独立成块，不与相邻正文拼成无效表格，也不参与重叠。

### 普通段落与重叠

- 普通段落优先在自然句号、问号、感叹号、分号或换行处切分。
- 单句仍超限时，使用完整向量文本反复校验最大原文前缀。
- 组合原子单元时以 350 tokens 为软目标、500 tokens 为硬上限。
- 只有同一具体标题路径被迫产生多个子片段时才添加重叠。
- 重叠复制完整尾部单元，不从句子、列表项、代码块或表格行中间截断。
- 原子单元导致无法精确达到 50 tokens 时，在目标两侧选择更接近的一组。
- 加入重叠后再次校验完整向量文本，禁止超过 500 tokens。

### 稳定哈希

`chunk_hash` 使用完整 `vector_text` 的 SHA-256。这意味着标题、标签、日记字段、标题路径或正文中任何会影响 Embedding 输入的变化，都会产生新 hash 并触发重新向量化。

## 为什么这样做

- 子片段是实际发送给硅基流动生成向量的文本，因此上限必须覆盖元数据和正文总和。
- 代码块、列表项和表格行是 Markdown 的结构原子；为了凑 token 数从中间切断会破坏语义和可读性。
- 父片段可以合并短章节，但子片段需要更具体的标题路径才能提供高精度召回和来源展示。
- 固定重叠不能跨章节，否则会把不同主题混入向量；同章节重叠也应重复完整语义单元，而不是机械复制 token 字符串。
- 图片路径可能包含私人目录结构，链接 URL 也可能包含敏感参数；向量文本只保留可见语义，精确标识符交给 MySQL 关键词检索。
- 对无法满足结构规则和硬上限的原子单元明确失败，比静默产生损坏或超限索引更可诊断。

## 自动化测试

新增 20 个子片段测试，覆盖：

- 配置边界。
- 普通笔记与日记元数据互斥规则。
- 普通笔记和日记向量文本格式。
- 图片 alt、图片路径、链接文字和链接 URL 处理。
- `parent_id`、稳定顺序、500-token 硬上限和稳定 hash。
- 具体兄弟章节标题路径和禁止跨章节重叠。
- 适配时完整保留代码块。
- 长代码块按行切分并重复围栏。
- 长列表只在完整列表项之间切分。
- 超长单列表项明确失败。
- 长表格按行切分并重复表头。
- 超长单表格行明确失败。
- 同一长章节添加完整单元重叠。
- 原子重叠选择距离目标 token 更近的一侧。
- 元数据变化导致 `chunk_hash` 变化。
- 空父片段不产生子片段。

## 真实 BGE-M3 tokenizer 验证

使用第 5 步已校验的 `BAAI/bge-m3` tokenizer，对包含标题、100 段中英混合正文、Markdown 图片和链接的父片段执行默认 `350 / 500 / 50` 分割。

结果：

~~~text
子片段数量：7
最大完整向量文本：398 tokens
各片段 token 数：362、398、398、398、398、398、164
连续片段重叠：42 tokens
图片路径进入向量文本：否
链接 URL 进入向量文本：否
~~~

42-token 重叠来自完整语义单元，处于规范建议的 40–60 token 范围内。
