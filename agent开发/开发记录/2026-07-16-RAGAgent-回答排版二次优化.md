# RAGAgent 回答排版二次优化

日期：2026-07-16

## 截图中发现的问题

- 回答正文使用衬线字体且字号偏小，中文技术内容阅读吃力。
- 接口章节以 A/B/C 粗体文本显示，没有稳定的标题层级。
- 水平分隔线过多，章节之间出现大面积无效留白。
- 列表项间距不统一，正文、字段说明和代码示例的关系不清楚。
- 深色代码块面积过大，但代码字号仍偏小，视觉重量与信息价值不匹配。

## 做了什么

- Agent 回答正文改为中文屏幕阅读更清晰的无衬线字体体系。
- 回答容器宽度从 760px 调整到 820px，并增加合理的正文内边距。
- 为 Markdown 的 `h1` 至 `h4` 建立完整字号、间距和颜色层级。
- 二三级标题使用克制的金色竖线标识，便于快速扫描接口章节。
- 对模型历史回答中常见的“整行粗体标题”增加兼容样式，使旧回答也能呈现为章节标题。
- 弱化水平分隔线并缩小上下间距。
- 统一无序列表、有序列表、列表标记和嵌套段落的间距。
- 重做行内代码样式，使接口路径与普通正文区分但不过度突出。
- 缩短代码块内边距，增加 `CODE` 标识，调整阴影、圆角、字号和行高。
- 增加表格、引用块和粗体内容的统一样式。
- 更新 Knowledge Agent Prompt，要求新回答：
  - 使用 `##` 或 `###` 作为章节标题；
  - 不使用 A/B/C 字母标题；
  - 不使用水平分隔线；
  - JSON、请求体和响应体必须使用带语言标记的代码块；
  - 列表保持紧凑，不在每个列表项之间插入空行。
- Prompt 版本升级为 `knowledge-readonly-v2`。

## 为什么这样做

只修改 CSS 只能改善已有回答的视觉效果，无法阻止模型继续生成松散的 A/B/C 结构和大量分隔线。因此本次同时约束模型输出结构和前端 Markdown 排版，让新回答结构稳定，旧回答也能通过兼容样式改善。

## 验证

- Vite 生产构建通过，共转换 1747 个模块。
- Knowledge Agent 与 API 专项测试 35 项通过。
- Django 系统检查通过。
- 没有修改 RAG 检索、会话记忆或只读权限边界。
