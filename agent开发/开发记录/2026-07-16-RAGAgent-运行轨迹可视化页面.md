# RAGAgent 运行轨迹可视化页面

日期：2026-07-16

## 做了什么

- 在知识对话的每条 Agent 回答下增加“查看 RAG 运行轨迹”入口。
- 新增独立组件 `KnowledgeRunTracePanel.vue`，没有把诊断展示逻辑混入对话页面。
- 新增前端服务方法，通过回答中的 `run_id` 调用脱敏轨迹接口。
- 使用右侧抽屉展示运行概览、阶段时间轴、阶段耗时、检索通道状态和最终候选来源。
- 混合检索区域展示：
  - 语义检索是否可用；
  - 是否降级为关键词检索；
  - Dense 候选数量；
  - 关键词候选数量；
  - 最终候选的笔记编号、章节路径和融合分数。
- 点击候选来源可以直接跳转到对应笔记。
- 对过期轨迹、其他账号的轨迹和网络异常提供明确提示及重试操作。
- 移动端使用全宽诊断面板，并支持减少动画的系统设置。

## 为什么这样做

只提供 JSON 接口时，排查人员仍然需要手工比较事件顺序、耗时和候选数据。纵向时间轴能直接呈现一次问答从请求校验、上下文加载、混合检索、工具执行、模型调用到结果落库的顺序。

诊断面板放在当前回答旁边，可以确保打开的是该条回答对应的 `run_id`，避免复制错误。采用独立组件和独立服务方法，是为了保持知识对话页面只负责会话编排，轨迹页面只负责诊断展示。

## 页面使用方法

1. 在知识对话页面发送问题或打开已有历史对话。
2. 点击 Agent 回答下方的“查看 RAG 运行轨迹”。
3. 先检查顶部 HTTP 状态和总耗时。
4. 检查“检索通道”是否发生降级。
5. 沿时间轴查看耗时异常或失败阶段。
6. 在“混合检索完成”节点检查候选笔记、章节和分数，并可直接打开笔记核对。

运行轨迹默认只保留一小时。页面仍然不会显示用户问题、重写查询、笔记正文、模型完整回答、JWT 或 API Key。

## 验证

- Vue 模板和组件通过 Vite 生产构建。
- 构建共转换 1745 个模块，无编译错误。
- 没有新增第三方前端依赖。
- 后端权限和轨迹数据结构沿用已通过的 353 项后端测试结果。
