# RAGAgent 用户输入重写

日期：2026-07-15

## 做了什么

1. 为 Knowledge Agent 增加检索查询重写能力。
2. 重写由当前 DeepSeek 对话模型完成，使用独立的严格 JSON Prompt：

```json
{"query":"重写后的检索查询"}
```

3. 重写只用于 `search_notes`，原始用户问题继续用于：
   - 最终回答；
   - 日记空字段判断；
   - 权限和安全判断；
   - 用户可见对话内容。
4. 最终采用“原检索为空后再重写”的保守策略：
   - 先使用原始输入检索；
   - 原检索没有父片段时，调用 DeepSeek 重写；
   - 使用重写查询重试一次检索；
   - 如果重写仍无结果，按原有资料不足流程处理。
5. 精确单日日记查询不调用重写，直接使用日期过滤读取日记。
6. 重写返回非法 JSON、空字符串、过长文本、工具调用或模型异常时，安全退回原始问题，不阻断 Agent。
7. 增加 `AGENT_QUERY_REWRITE_ENABLED` 配置，默认启用。
8. 日志只记录是否发生重写和 Prompt 版本，不记录原问题或重写正文。

## 为什么这样做

直接用重写结果替换原输入，会改变已经通过验收的候选排序，并可能丢失接口路径、文件名、错误码等精确标识。将原问题与重写结果直接拼接也会改变向量和关键词得分。

因此采用失败后重写：正常查询保持原来的稳定检索路径，只有原检索完全没有结果时才使用重写补救。这既提供了输入重写能力，又不让模型改写干扰已有高质量召回和来源选择。

## 测试覆盖

- 原检索为空时使用重写查询重试。
- 检索使用重写结果，但最终模型仍收到原始用户问题。
- 非法重写结果自动退回原始问题。
- 原检索有结果时不触发重写。
- 精确日记查询保持原路径。
