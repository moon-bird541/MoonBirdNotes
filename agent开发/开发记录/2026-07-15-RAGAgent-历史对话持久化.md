# RAGAgent 历史对话持久化

日期：2026-07-15

## 做了什么

为 Knowledge Agent 增加持久化历史对话功能，每次有效问答请求都会记录到 MySQL。

支持：

- 首次发送问题时自动创建会话；
- 根据第一条问题生成会话标题；
- 每次成功问答记录问题、回答、来源、资料不足状态和 `run_id`；
- Agent 或模型异常时记录问题、失败状态和结构化错误码；
- 历史会话列表；
- 打开历史会话；
- 在历史会话中继续追问；
- 删除历史会话；
- 不同管理员只能访问自己的会话；
- 服务端使用最近三轮成功问答构造最多六条上下文消息。

## 数据结构

### KnowledgeConversation

保存：

- UUID；
- 所属用户；
- 会话标题；
- 创建时间；
- 最后更新时间。

### KnowledgeConversationTurn

保存：

- UUID；
- 所属会话；
- `run_id`；
- 用户问题；
- Agent 回答；
- 来源 JSON；
- 资料不足状态；
- 成功或失败状态；
- 结构化错误码；
- 创建时间。

### 数据模型

- `backend/agent/conversation_store.py`

负责创建会话、加载服务端历史、记录成功/失败问答以及序列化会话，不把存储逻辑放进 Agent 主文件。

### API

```text
POST   /api/agent/knowledge/chat/
GET    /api/agent/knowledge/conversations/
GET    /api/agent/knowledge/conversations/<conversation_id>/
DELETE /api/agent/knowledge/conversations/<conversation_id>/
```

聊天响应新增：

```json
{"conversation_id":"uuid"}
```

继续历史会话时请求携带：

```json
{"message":"继续追问","conversation_id":"uuid"}
```

## 页面设计

- 桌面端在消息区域左侧增加 238px 历史轨道；
- 显示标题、更新时间和问答轮数；
- 当前会话使用金色细线标记；

- 历史轨道不挤占现有主侧边栏；
- 删除会话前需要用户确认。

## 为什么这样做

- localStorage 无法跨浏览器同步，也不适合作为正式历史记录。
- 仅使用 `session_id` 无法恢复消息正文和来源。
- 服务端持久化后，可以在重新登录或刷新页面后继续会话。
- 继续会话时由服务端读取历史，避免客户端篡改已保存上下文。
- 会话存储服务与 Agent 推理分离，防止数据库代码和 RAG 编排混在同一个文件中。

## 安全与隐私

- 历史记录包含用户问题和 Agent 回答，属于业务数据。
- API 使用当前管理员身份过滤会话。
- 猜测或传入其他用户的 UUID 会返回 404。
- 删除会话会级联删除全部问答记录。
- API Key、模型原始响应和笔记正文不会额外写入历史表。
- 来源只保存已验证后的受控结构。

## 会话隔离补充验证

不同历史会话的上下文严格按照 `conversation_id` 隔离：

- 继续会话 A 时，只读取会话 A 最近三轮成功问答；
- 继续会话 B 时，只读取会话 B 最近三轮成功问答；
- 不会把当前用户其他会话的内容拼入上下文；
- 查询条件同时包含 `conversation_id` 和当前登录用户；
- 其他管理员即使获得会话 UUID，也无法读取、删除或追加问答；
- 越权读取和追加统一返回 404，不暴露会话是否真实存在。

本次补充了双会话、双用户隔离回归测试，并修复聊天视图把 Django `Http404` 误包装为 500 的状态码问题。

补充验证后全量测试：343 项通过。
