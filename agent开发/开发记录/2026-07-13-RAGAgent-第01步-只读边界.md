# RAG Agent 第 01 步开发记录：确定第一版只读边界

## 本次完成的范围

本次只完成 RAG Agent 实际执行顺序的第 1 步“确定第一版只读边界”，没有提前创建 Django App、数据模型、向量索引或 Agent 运行代码。

## 做了什么

1. 完整阅读并核对了 `开发规范.md`、`开发顺序.md`、`RAGAgent开发步骤.md` 和 `PRODUCT_RULES.md`。
2. 新增 `RAGAgent第一版只读边界.md`，统一定义：
   - 第一版 RAG Agent 的身份是只读 Knowledge Agent。
   - 六个允许的只读工具。
   - 写工具为空，以及数据库、代码、文件、网络和跨 Agent 调用禁令。
   - MySQL、父片段和 Qdrant 的真实数据与派生数据关系。
   - 普通笔记、日记、标签、日期、软删除和历史版本的检索边界。
   - 检索正文是不可信数据，不能提供指令或授权。
   - 固定输出结构、资料不足行为和后续可验证验收项。
3. 在 `RAGAgent开发步骤.md` 的第一版目标后标记第 1 步已完成，并链接到边界文档。
4. 建立统一目录 `agent开发/开发记录/`，并用 `README.md` 固定后续开发记录的内容和命名约定。

## 为什么这样做

- 三份 Agent 文档都要求先确定边界，再建设数据和工具层。先写 Agent 或接入向量库会让权限、数据来源和验收条件变得含糊。
- Knowledge Agent 的核心安全属性不是 Prompt 中声称“只读”，而是能力列表中根本没有写工具，也没有任意数据库、代码、文件或网络入口。
- `PRODUCT_RULES.md` 明确区分普通笔记与日记，并规定标签只服务普通笔记；将这些规则写入 RAG 边界，可以避免后续索引和检索实现破坏现有产品行为。
- 将检索正文定义为不可信数据，是防止笔记中的提示词注入扩大 Agent 权限的前提。
- 单独保存开发产物与开发记录，便于后续分别查阅“当前规范”和“当时为什么这样实现”。

## 如何验证

- 对照 `RAGAgent开发步骤.md` 第 1 节，允许能力、禁止能力和不可信检索内容三项完成标准均已在边界文档中明确。
- 对照 `开发规范.md`，只读工具清单严格为 `search_notes`、`get_parent_chunks`、`get_note`、`get_note_section`、`get_diary_by_date`、`list_tags`。
- 对照 `PRODUCT_RULES.md`，边界文档明确了普通笔记搜索排除日记、全局知识检索可包含两者、标签不用于日记、默认排除软删除内容等规则。
- 本步只修改和新增 Markdown 文档，不涉及运行时代码，因此无需执行 Django 检查或数据库迁移。
