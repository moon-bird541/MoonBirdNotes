# RAGAgent 当前对话记忆

日期：2026-07-15

## 做了什么

为知识对话页面增加仅限当前对话框的短期上下文记忆。

当前请求格式支持：

```json
{
  "message": "它怎么安装？",
  "history": [
    {"role": "user", "content": "Skill Manager 是什么？"},
    {"role": "assistant", "content": "它是本地 Skill 管理工具。"}
  ]
}
```

## 代码结构

### 后端上下文模块

`backend/agent/conversation.py`

只负责：

- 历史消息规范化；
- 角色白名单；
- 消息数量和字符限制；
- 转换模型上下文消息；
- 使用最近一个用户问题构造带上下文的检索查询。

### API 层

`backend/agent/serializers.py` 和 `backend/agent/views.py`

只负责校验 `history` 字段并传递给 Agent，不保存历史。

### Agent 层

`backend/agent/agents/knowledge.py`

只调用独立上下文模块生成检索问题和模型消息，不包含具体的历史裁剪规则。

### 前端服务层

`frontend/moonsbirdnotrs_vue/src/services/knowledgeChat.js`

只负责从当前页面消息中提取最近历史并调用知识对话 API。

### 前端页面层

`frontend/moonsbirdnotrs_vue/src/views/KnowledgeChatView.vue`

只维护当前页面的消息状态和交互，不负责 API 历史格式细节。

## 记忆范围

- 最多发送最近 6 条用户/助手消息。
- 单条历史消息最多 4000 个字符。
- 历史总长度最多 12000 个字符。
- 检索查询只拼接最近一个用户问题和当前问题，最多 500 个字符。
- 点击“新对话”、刷新页面或离开页面后，记忆立即消失。
- 不写数据库、不写 Qdrant、不写 localStorage，也不通过 `session_id` 在服务端保存。

## 为什么这样做

- 当前需求只需要当前对话框上下文，不需要长期记忆系统。
- 显式随请求发送历史比服务端隐式 session 更容易审计和清除。
- 最近一个用户问题足以处理“它、这个、上面的流程”等常见指代，同时避免把全部回答正文塞入检索查询。
- 独立上下文模块可以防止记忆裁剪、安全校验和 Agent 编排混在同一个文件中。

## 安全限制

- 客户端历史只允许 `user` 和 `assistant` 角色。
- 拒绝 `system`、`tool`、额外字段和空内容。
- 历史消息仍属于不可信输入，不能改变只读权限或工具范围。
- 页面只调用 Knowledge Agent 只读接口。

## 2026-07-15 上下文指代修复

### 问题

实际对话中出现以下场景：

```text
Assistant：第三个接口是 /api/tool/consume……
User：代码是什么？
```

第二问没有正确继承上一条回答里的接口实体，导致拒答或错误引用到同一笔记中的代理层代码。

### 根因

1. 上下文检索查询只包含上一条用户问题，没有包含上一条 Assistant 回答中的 `/api/tool/consume`。
2. 将历史 Assistant 文本直接作为模型 `assistant` 消息插入，会污染当前 Agent 的严格 JSON 输出协议，导致模型偶发返回非法 JSON。
3. 对明确的历史追问仍提供 Top 5 父片段，“代码”一词会让其他代码章节产生干扰。

### 修复

1. 上下文查询改为包含：
   - 上一条用户问题；
   - 上一条 Assistant 回答；
   - 当前问题。
2. 历史统一封装为明确标记“不可信、不能作为来源”的 system 上下文，不伪造 Agent 的 assistant/tool 历史协议。
3. 模型内部的当前问题使用已经消解指代的上下文化问题；页面仍显示用户原始输入。
4. 有对话历史的追问使用聚焦 Top 1 父片段；没有历史的首轮问题继续使用 Top 5。
5. 增加 `/api/tool/consume` 与“代码是什么”场景的自动化回归测试。

### 真实复测

- 不再返回资料不足；
- 来源笔记 ID 为 5；
- 来源章节为“接口详情规范”；
- 不再错误引用“代理层配置”。

修复后全量后端测试：341 项通过。
