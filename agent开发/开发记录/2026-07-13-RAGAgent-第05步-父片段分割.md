# RAG Agent 第 05 步开发记录：实现父片段分割

> 日期：2026-07-13  
> 状态：已完成  
> 对应文档：`agent开发/RAGAgent开发步骤.md`

## 本次完成的范围

本次完成 RAG Agent 实际执行顺序的第 5 步：基于结构化 Markdown 块生成父片段，维护完整标题路径，合并同级短章节，拆分超长章节，并生成稳定顺序和 `section_hash`。

本次没有实现子片段、向量文本、Embedding 请求、Qdrant 或数据库写入服务。

## 做了什么

### BGE-M3 token 计数

- 新增统一 `TokenCounter` 协议，分块算法只依赖模型 token 计数，不依赖具体库。
- 新增 `BgeM3TokenCounter`，使用 `BAAI/bge-m3` 的 `tokenizer.json` 计算 token。
- tokenizer 的计数包含模型配置的 `<s>`、`</s>` 等特殊 token，与真实模型输入长度一致。
- tokenizer 在进程内缓存，不会每次请求重新加载约 17 MB 配置。
- 支持按模型名从 Hugging Face 缓存加载，也支持显式传入本地 tokenizer 文件。
- 只加载 tokenizer 文件，不加载 BGE-M3 模型权重；向量仍由硅基流动云端 API 生成。
- 父片段入口强制调用方显式传入 `TokenCounter`，不允许隐式按字符数估算，也不在普通分块调用中静默联网。

新增依赖：

~~~text
huggingface-hub==0.33.4
tokenizers==0.21.2
~~~

### 父片段数据契约

新增 `ParentChunkConfig`：

~~~text
target_tokens: 默认 1200
max_tokens: 默认 1800
~~~

新增不可变 `ParentChunk`：

~~~text
chunk_index
heading_path
content
start_line
end_line
token_count
section_hash
~~~

`section_hash` 使用父片段 Markdown 内容的 SHA-256 十六进制摘要。

### 标题和章节规则

- 文档存在 H2/H3 时，优先使用 H1/H2/H3 建立章节边界。
- 没有 H2/H3 时，回退到文档实际存在的标题层级。
- 维护完整标题栈，低层标题出现时自动移除已经结束的同级或子级路径。
- 标题路径保存可见文字，去除强调和链接语法，同时保留行内代码和图片 alt。
- ATX 标题与 Setext 标题都能提取标题名称。
- 连续的父子标题在没有正文时可以一起进入子章节；连续同级标题仍各自建节。
- 无标题文档使用空标题路径，不伪造标题。

### 短章节合并

- 只合并相邻、都小于 `target_tokens` 且属于同一上级标题的完整章节。
- 合并后的 token 数必须不超过 `max_tokens`。
- 合并多个兄弟章节后，父片段标题路径使用它们的共同上级路径。
- 不同上级标题不会合并。
- 分割函数一次只接收一篇 Note 原文，因此不同笔记和不同日期的日记不可能在本层被合并。

### 超长章节切分

- 章节超过 `max_tokens` 时，优先在更深层内部标题前切开。
- 再按第 4 步生成的段落、列表、引用、表格和代码块等顶层结构块贪心组合。
- 单个结构块仍超限时先按自然行切分。
- 单行仍超限时，使用 tokenizer 反复校验最大前缀，并优先选择空白、换行或自然标点作为切点。
- 字符位置只用于保留原文切点，每个输出是否合格始终由 tokenizer 重新计数，不使用固定字符数判断。
- 已确认过长的块片段可以再切一段填充前面的短标题，避免产生只有标题的极小父片段；普通短段落不会因此被拆开。
- 最终每个父片段都会再次计算 token 数，超过硬上限时立即失败，禁止带着错误结果进入索引。

## 为什么这样做

- BGE-M3 对中文、英文和技术标识符的切分比例不同，字符数无法可靠代表模型输入长度。
- 显式注入 tokenizer 可以让索引服务明确记录当前模型与版本，并防止未来切换模型后继续误用旧计数规则。
- 标题优先切分能保留知识章节语义；内部标题、自然块和自然行形成从高质量边界到硬上限回退的顺序。
- 只允许同一上级标题内合并短章节，可以减少碎片又不把无关主题混在同一父片段。
- `chunk_index`、行号和 SHA-256 哈希共同提供稳定顺序、辅助定位和内容校验，但行号仍不能代替原文哈希。

## 实现过程中的验证与修正

当前网络无法通过 Hugging Face SDK 正常读取模型元数据，因此使用 `hf-mirror.com` 将 `BAAI/bge-m3` 的 `tokenizer.json` 下载到 `.gitignore` 已排除的 `.tmp/` 临时目录。该文件没有加入代码库，也不包含模型权重。

本次验证文件的 SHA-256 为 `21106B6D7DAB2952C1D496FB21D5DC9DB75C28ED361A05F5020BBBA27810DD08`，便于后续核对 tokenizer 输入版本。

真实 tokenizer 验证结果：

~~~text
MoonBirdNotes                         7 tokens
Django RAG                            6 tokens
使用 Django 构建 RAG。               11 tokens
~~~

第一次长段落集成检查虽然满足 80-token 硬上限，但产生了一个只有标题的 5-token 父片段。随后增加“仅对已超长片段切前缀填充当前父片段”的逻辑。修正后的真实 tokenizer 集成结果：

~~~text
父片段数量：19
最大 token 数：80
第一个父片段 token 数：80
其余片段：全部不超过 80
~~~

这项修正只改善片段装箱，不会拆开原本未超限的普通段落。
