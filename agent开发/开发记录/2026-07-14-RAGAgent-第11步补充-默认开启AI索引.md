# RAGAgent 第 11 步补充：默认开启 AI 索引

日期：2026-07-14

## 本次做了什么

根据用户确认，将 Note 的 `ai_indexing_enabled` 策略从“默认关闭”调整为“默认开启”：

- 新建普通笔记和日记默认设置为 `ai_indexing_enabled=true`。
- 新增 `notes.0020_enable_ai_indexing_by_default` 数据迁移，将全部现有 Note 的授权状态统一更新为 `true`。
- 保留逐篇关闭能力；明确关闭或处于回收站的 Note 仍不会被索引服务上传。
- 更新后台任务测试，覆盖新建 Note 默认开启并创建 `note_created` 任务，以及显式关闭后重新开启/关闭的行为。
- 更新 README 和 RAGAgent 开发步骤，避免文档继续描述旧的默认关闭策略。

## 为什么这样做

用户要求先默认允许所有笔记向量化。默认值必须同时覆盖“现有数据”和“以后创建的数据”，否则只改模型默认值会遗漏数据库中已有 Note，只改现有数据又会让新 Note 继续默认关闭。

逐篇字段仍然保留，因为它是云端数据边界的一部分：当某篇笔记包含不应发送给硅基流动的内容时，可以单独关闭后续索引，并由现有后台任务流程清理对应 Qdrant 索引。

## 迁移为什么不会立即上传内容

数据迁移使用历史模型的 `QuerySet.update()` 直接更新 MySQL 字段。该方式不会调用 `Note.save()`，也不会触发 RAG signals，因此：

- 不会创建 `RagIndexJob`。
- 不会调用硅基流动 Embedding API。
- 不会写入 Qdrant。
- 不会修改 Note 原文。

迁移完成只代表所有 Note 获得向量化授权。现有 Note 需要显式执行 `python manage.py rebuild_rag_index` 才会开始全量向量化；新建或后续修改的已授权 Note 则按现有流程进入后台队列。
