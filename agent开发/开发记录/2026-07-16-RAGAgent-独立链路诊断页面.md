# RAGAgent 独立链路诊断页面

日期：2026-07-16

## 做了什么

- 移除了知识对话回答下方的“查看 RAG 运行轨迹”按钮和弹出式诊断抽屉。
- 新增独立页面 `/rag-traces`，并在系统侧边栏增加“RAG 链路”固定入口。
- 页面左侧展示当前管理员最近 100 条运行记录，右侧展示所选运行的完整阶段时间轴。
- 页面顶部支持直接输入 `run_id` 查询指定链路。
- 新增 `GET /api/agent/knowledge/runs/`，为诊断页面提供最近运行索引。
- 运行索引只返回 `run_id`、`conversation_id`、状态、错误码和创建时间，不返回问题、会话标题或回答正文。
- 轨迹详情继续展示 HTTP 状态、总耗时、检索降级、候选数量、工具执行、模型调用和会话持久化状态。
- 最终候选笔记仍可以直接跳转打开核对。

## 为什么这样改

运行轨迹属于系统诊断能力，不属于单条回答的正文操作。放在回答下方会干扰正常对话阅读，也不便于连续比较多次运行。

独立诊断页面可以把“最近运行索引”和“完整链路详情”同时放在一个工作区内，更适合定位同一问题多次执行的差异。固定导航入口也让排查人员无需先找到某条回答。

## 权限与安全

- 运行列表和轨迹详情都要求管理员权限。
- 运行列表严格按当前账号隔离。
- 其他管理员无法从列表看到运行，也无法通过 run_id 读取详情。
- 页面和接口均不返回用户问题、重写查询、笔记正文、模型完整回答、JWT 或 API Key。
- 轨迹缓存默认保留一小时；运行索引可能仍存在，但详情过期时页面会明确提示。

## 验证

- Vite 生产构建通过，共转换 1747 个模块。
- Django 系统检查通过。
- 轨迹、运行列表和 Agent API 专项测试 20 项通过。
