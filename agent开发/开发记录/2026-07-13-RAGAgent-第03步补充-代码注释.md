# RAG Agent 第 03 步补充记录：完善代码注释

> 日期：2026-07-13  
> 状态：已完成  
> 原因：统一当前及后续 Agent/RAG 代码的注释要求

## 本次完成的范围

本次为第 2、3 步已经新增的 RAG/Agent 应用骨架、数据模型和测试补充中文注释，并将后续代码注释要求加入统一开发规范。

本次只修改注释、文档字符串和开发规范，没有修改数据库字段、业务逻辑、迁移内容或 API 行为。

## 做了什么

- 为 `RagParentChunk`、`RagIndexState`、`RagIndexJob` 增加类职责说明。
- 为三个模型的关键字段增加中文注释，说明真实数据来源、哈希用途、版本用途、任务状态和时间字段含义。
- 为唯一约束、检查约束和查询索引增加原因说明。
- 明确解释 `RagIndexJob` 不使用 `note + source_hash` 永久唯一约束的原因。
- 为 `rag.services`、分块、Embedding、检索、管理命令、Agent 和工具包补充中文模块边界说明。
- 为 AppConfig 和模型测试补充职责或测试意图说明。
- 在 `agent开发/开发规范.md` 新增“代码注释规范”，要求后续开发同步添加必要中文注释。
- 保持 Django 自动生成的 `0001_initial.py` 不变。

## 为什么这样做

- RAG 中的数据真实来源、派生数据、索引版本和最终一致性关系仅看字段名无法完整理解，需要注释避免后续误用。
- 权限边界和索引约束属于不能被普通重构破坏的设计规则，注释应解释约束存在的原因。
- 将要求写入统一开发规范，可以保证后续步骤继续执行，而不是只补当前文件。
- 自动生成迁移文件应保持与 Django 生成结果一致；手工注释迁移会增加无意义差异，设计原因应保留在模型代码和开发记录中。

## 注释原则

- 说明“为什么”和“不能破坏什么”。
- 对明显语法不逐行复述，避免注释比代码更难维护。
- 模块职责、公开边界、数据来源、安全规则、非直观算法和异常处理必须说明。
- 测试名称已经足够清楚时不重复解释，只有隐藏前提和业务原因才增加注释。
